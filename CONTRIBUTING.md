# Contributing

Changes should close a defined clarity, reproducibility, review or experimental gap. Preserve the separation between the concept paper, engineering package and future experimental results.

## Working rules

1. Consult the current roadmap and record the reason for each substantive change.
2. Identify the affected artifact and version. Update the changelog and inventory together.
3. Keep editable sources beside their reading copies where supplied. Do not call an extracted or rewritten text the original source.
4. Preserve engineering filenames, units, relative paths, schemas and provenance. Review dependencies before reorganizing a release.
5. Label synthetic data explicitly. Keep raw measurements immutable and separate from simulations and derived analysis.
6. Record reviewer findings, severity, proposed resolution and disposition. Critical or major issues need documented resolution before a final freeze.
7. Use the project change-request pattern `SETI-CR-YYYY-NNN` for controlled changes after candidate freeze.

## Verification

For imported originals, record a SHA-256 hash and source location. Validate document links and matching versions. For software changes, run the supplied schema validation and scoring checks using documented dependencies; report actual results and limitations. Hardware acceptance requires hardware evidence and cannot be inferred from synthetic tests.

Keep reviewer contact information and private correspondence outside material intended for publication. Confirm the selected license before distributing contributions.
